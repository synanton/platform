## Live fixes discovered during acceptance

The deployment found four gaps that the component/integration tests did not
cover. Each was fixed on the branch, rebuilt, redeployed, and the scenarios were
re-run against the final image.

1. **Missing `Clock` bean** (`ad4d81ed`). `CanonicalGraphCompletion` and
   `ActivationRecoverySweep` are Spring beans whose constructors require a
   `java.time.Clock`; Relix never defined one, so the new image crash-looped at
   startup. Integration tests construct these classes manually and could not see
   the wiring gap. Added a `Clock` bean in `RelixConfig`.
2. **`PARTIAL` graph commits were never promoted or activated** (`672d435c`).
   Live LLM extraction rejects some relations; `GraphWriter` correctly records
   `PARTIAL`, but the promotion producer only scanned `MENTIONS_COMMITTED` and
   the completion LWT only accepted that state. Accepted relations from a
   partial validation were therefore stranded. The producer now scans
   `MENTIONS_COMMITTED` and `PARTIAL`; the completion LWT accepts both. Only
   retirement remains gated on a complete extraction (ADR-029 §5).
3. **No scheduled source-fence reconciler** (`3faef3f0`). Promotion is
   fail-closed while the Neo4j `:SourceRevisionFence` is missing, but
   `SourceFenceReconciler` had no scheduled caller. Added
   `SourceFenceReconciliationSweep`, enabled by `RECONCILIATION_ENABLED=true`.
   This is the ADR-029 §11 repair path, not an authorization shortcut.
4. **Syntology NetworkPolicy excluded Relix** (`672d435c`). The new canonical
   identity lookup calls Syntology; the `syntology-allow-synflux` policy allowed
   only `synflux` and `ui`, so Relix timed out on `/v1/entities/{id}/type`.
   Added `relix` to the allowed sources
   ([`network-policy.txt`](artifacts/k8s-activation-654-2026-11-14/network-policy.txt)).

## What this proves

- The deployed artifact (not a locally constructed object graph) drives the
  real API → workflow → Cassandra → Neo4j chain.
- Accepted relations are promoted and activated even when validation rejects
  other relations from the same revision.
- The Neo4j source fence is repaired from Cassandra by the scheduled
  reconciliation path, so promotion does not require a test-only manual advance.
- A crash after graph commit is recovered by the scheduled sweep without a new
  generation and without duplicate graph rows.
- At-least-once re-delivery of `ActivationRequested` is a no-op for an already
  current revision.
- Promotion ownership survives a Relix restart while activation is outstanding.
- Tenant isolation holds for this revision in the live graph.

## What this does not prove

- **Read visibility:** these scenarios assert the lifecycle state, not that the
  search/read services return the new revision or hide the old one. Search
  projection is stamped by the existing search consumer; the read path is not
  part of this acceptance.
- **Source replacement / retirement:** only generation 1 is exercised.
  Supersede-and-retire behavior (#655/#656) is not covered.
- **Startup dependency (#692):** Relix still depends on Cassandra being available
  at startup. Cassandra was not restarted during this run; a Cassandra outage may
  still require a Relix restart.
- **Deployment digest chain:** the registry manifest digest, OCI revision label,
  and pod image ID were compared and agree. The local Docker `.Id` is not a
  usable comparison and was not used.
- **Recovery on a different scheduler cadence:** the acceptance used the shipped
  poll intervals. Recovery latency under longer or contended cadences is not
  measured.
- **New regression tests for the live-only fixes:** the four fixes were verified
  live and by the existing integration suite; dedicated tests for the `PARTIAL`
  promotion path and the fence sweep belong to the follow-up lifecycle work.
