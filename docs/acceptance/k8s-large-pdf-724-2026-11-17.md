directly against the same vLLM endpoint with the same prompt. Prompt tokens were

fix for this reproduction; it has not been adopted as the production default.

### Classification

The samples show that the dominant failure is candidate/extraction quality, not
a missing ontology vocabulary:

- `is_a` (406): mostly function words or sentence fragments
  (`The → Thirty`, `The → Search`, `Sustainability → Despite`,
  `Google Trends → And`). These are type/metadata statements or heuristic
  artifacts, not canonical object-property edges.
- `has` (62): mostly generic/underspecified (`Thirty → The`,
  `Google → We`). A few (`Google → AI`) are semantically plausible but still
  need a gold label and a typed contract.
- `includes` (29) and `part_of` (16): mostly fragments; a minority
  (`Carbon Sense Suite → Carbon Footprint`) are plausible partonomy but would
  require a canonical predicate and endpoint typing.
- `uses` (21): mixed; `Tree Canopy Insights → AI` and
  `TerrAdapt → Google Earth Engine` are plausible but generic. These are the
  strongest ontology-gap candidates in the sample, not a mandate to add a
  generic `uses` edge.
- `measures` (11), `requires` (10), and the long-tail predicates: mostly
  extraction/type errors. `requires` is already in the ontology, but the
  endpoints are typically `Concept → Concept`, so the failure is typing or
  domain/range, not vocabulary.

The earlier seven debug rows were not a representative sample; the reconciled
event counts are authoritative. The debug logger also omitted most per-candidate
lines even after the missing-endpoint instrumentation, so the aggregate
accounting, not ad-hoc log sampling, is the acceptance artifact.

Debug logging was temporary and has been removed; synflux is back to INFO
logging, two replicas, and `eval-smoke` provider `regex`. No ontology,
validation, or promotion rules were changed.

## Track A conclusion and next decision gate

The 0/564 result is dominated by extraction candidate precision, generic
`Concept → Concept` endpoints, and a small number of genuinely plausible
partonomy/usage relations. Adding ontology predicates now would admit many
garbage edges, so the next gate is:

1. build a small gold-labelled sample from the plausible `includes`, `part_of`,
   and `uses` cases;
2. fix extractor candidate filtering/typing/normalization evidence;
3. decide whether a narrowly scoped canonical predicate is justified.

No ontology or promotion change should be made from the aggregate counts alone.

## Findings

1. **Large-document relation cliff.** The short-doc canary accepted 8/12
   candidates (66.7%); this 104-page report accepted 0/564 (0%). This is a
   genuine quality/coverage finding, not a timeout or memory failure. It is
   consistent with the report's environmental/standards vocabulary falling
   outside the active enterprise ontology. The eval needs either ontology/rule
   coverage for this document class or an explicit large-document quality
   caveat.
2. **LLM output-cap failure (root-caused).** The original adapter used a
   2,048-token completion cap and discarded `finish_reason`. A direct replay
   produced `finish_reason=length` and invalid JSON at 2,048, then
   `finish_reason=stop` and valid JSON at 4,096 with the same 1,328-token prompt.
   This is output truncation, not input-context exhaustion. The production
   default remains unchanged pending the remaining reliability checks.
3. **Resource and timeout signals are acceptable.** Regex completed in ~5.1
   minutes (2.93 s/page), heap peaked at ~132 MiB, and no stage timeout fired.
   The regex path is not the resource-risk driver; relation validation is the
   dominant time.

## Decision

#724 remains open. Track B is root-caused and the source/resource measurement is
recorded, but Track A's 564-candidate rejection taxonomy is not yet reconciled,
and the LLM 4,096-token fix is not yet a production decision. Item 10 remains
not green.
